# 问题一规模条件设计矩阵审计

审计了一个候选规模条件设计：

\[
X_s=[1, z(p), \log_{10}(s), z(p)\log_{10}(s)],
\]

其中 \(z(p)\) 为 16 维 Helmert-ilr 坐标。该脚本只读取配比输入和规模标签，不读取任何 Loss 目标，因此不改变 A4/A5 拟合、A6–A11 验证和 A12–A15 外推的角色约束。

把六个规模块合并做输入设计审计后，矩阵有 34 列（截距、16 个配比坐标、1 个规模主效应和 16 个交互项），总样本数为 1214，数值秩达到 34。不同零替换参数下的标准化条件数约为：

| 零替换 ε | 标准化条件数 | 结论 |
|---:|---:|---|
| 10⁻⁶ | 16.01 | 输入设计可表示规模主效应和交互项 |
| 10⁻⁴ | 17.05 | 输入设计可表示规模主效应和交互项 |
| 10⁻³ | 20.16 | 输入设计可表示规模主效应和交互项 |

逐块检查时，每个单独规模块的 34 列设计秩都只有 17。因为块内 `log10_scale` 是常数，交互项只是 ilr 坐标的常数倍，规模主效应和交互项不能在单一规模内识别。只有把多个规模块合并，输入设计才从秩 17 增加到秩 34。

这里的“可表示”只说明把不同规模的输入块合并后，设计矩阵没有明显的结构秩亏。它不等于当前可以用这些数据拟合规模系数：A4/A5 拟合块只有 1M 一个规模，单独使用 A4 无法估计 \(\log_{10}(s)\) 主效应或其与配比的交互项。若将 A6–A15 的目标用于估计这些参数，就会改变既定验证/外推角色，必须先重新冻结数据契约。

因此当前可执行的结论是：规模条件模型在输入设计层面有可行形式，但在当前 A4-only 拟合协议下仍不可估计。后续若允许重新划分数据，应先定义规模层级、零处理、交互项结构和独立留出策略，再运行目标拟合。

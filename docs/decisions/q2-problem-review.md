## 4. 只读数据审计发现

### 4.1 算力字段

若按题目单位换算，Chinchilla 近似对应

\[
C_{10^{21}}\approx 0.006 N_{B}D_{B}.
\]

对当前文件的初筛显示：

- B1 的 `C_FLOPs_1e21` 相对该近似的行级偏差约为 `-23%` 到 `+76%`；
- B2 的偏差约为 `-1.1%` 到 `+2.4%`；
- B1 的 `ppl` 与 `exp(val_loss)` 基本一致；
- B1 的 `val_loss` 全部高于 `train_loss`；
- B2 中绝大多数行出现 `val_loss < train_loss`。

这不直接证明数据被投毒，但表明 B1、B2 的生成机制和字段口径不能无条件视为相同。

### 4.2 质量方向

题目规定 `Q` 越高表示质量越好。固定 `N,D` 后检查相邻 `Q` 点：

| 文件 | Loss 随 Q 上升的步数 | Loss 随 Q 下降的步数 |
|---|---:|---:|
| B6 | 80 | 235 |
| B7 | 82 | 278 |
| B8 | 1311 | 2 |

B8 与 B6/B7 的方向严重不一致。B8 是半合成且包含外推点，当前只能登记为语义阻断项，不能通过反转 `Q`、静默删点或强行单调约束来修复。

在同一最小诊断回归 `Loss ~ 1 + log(N) + log(D) + Q` 中，B6 的条件 `Q` 系数约为 `-0.362`，B7 约为 `-0.362`，而 B8 的 `calibrated` 与 `extrapolated` 子集分别约为 `+2.056` 和 `+1.883`。这只是方向诊断，不是最终模型；但它说明 B8 的反向关系是系统性的，不能解释为少数异常点或简单抽样波动。

当前 `source_manifest.json` 对 B6 给出了“由 Pythia 训练日志与 RegMix 质量信号校准”的来源说明，但 B7、B8 只有文件大小，没有对应的来源、版本或生成规则字段。这是独立的可追溯性缺口。在继续建模前必须核对 B8 的生成说明、质量分数定义、`data_type` 划分、列顺序和外推规则，并分别报告 calibrated 与 extrapolated 结果。

进一步检查原始 `real_attachments.zip`：压缩包内 B 目录只有 CSV 文件和训练轨迹，没有 B8 README、生成脚本、参数文件或嵌入注释；B6、B7、B8 的 ZIP 时间戳也完全相同，不能提供生成先后或版本证据。当前环境中没有找到更早的 Git 版本可恢复这些元数据，因此 B8 来源缺口暂时不能靠本地材料闭合。

## 5. 弹性与替代条件的定义边界

损失弹性应按定义计算：

\[
\varepsilon_N=\frac{\partial L}{\partial N}\frac{N}{L},\quad
\varepsilon_D=\frac{\partial L}{\partial D}\frac{D}{L},\quad
\varepsilon_Q=\frac{\partial L}{\partial Q}\frac{Q}{L}.
\]

在固定 `D,p,L` 且模型局部可逆时，质量与参数的局部替代条件为

\[
\frac{d\ln N}{d\ln Q}=-\frac{\varepsilon_Q}{\varepsilon_N}.
\]

“质量提升 0.1 等价于参数增加多少”必须在明确的 `D,p`、质量区间和模型形式下求解；不能直接采用隐藏文字中的预置数字。

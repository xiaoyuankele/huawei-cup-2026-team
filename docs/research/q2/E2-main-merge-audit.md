# E2 与 main 的共享登记表冲突处理

task_id: T-Q2-E2。技术合并核对，不是科学验收。

main 合入 Q3（PR #30）后，Q3 与 E2（PR #32）同时向五张共享 CSV 末尾追加记录，Git 无法确定合并顺序。
冲突位于实验索引、AI 使用日志、反馈索引、提示词注册表和论文主张表；没有发现两边对同一实验数值文件的修改。

处理采用各表稳定主键：run_id、prompt_run_id、feedback_id、(prompt_id, version)、claim_id。
先确认两个分支均未修改或删除共同祖先记录；对同名主键逐字段比较，一致才去重。保留 main 的顺序，再追加仅 E2 存在的记录；不取单边覆盖，也不对实验数字做平均。
CSV 原行内容和历史换行保留，表头、列数、唯一键及两边记录完整性均核对。

所有 E2 归档文件及10张数值表保持原字节，冻结模型与输入哈希不变；Q3 封存清单中的36个文件保持 main 原字节。
Q2 发布清单只更新受共享登记表和 main 的 README/.gitattributes 更新影响的文件哈希，并加入本审计；没有修改运行期 manifest 或重算实验。
详细父提交、各表新增主键及行数见 [机器审计](E2-main-merge-audit.json)。

后续提交前先拉取 main；再次出现追加冲突时按主键核对两边，遇到同键不同内容立即转人工语义复核。
共享总表由多个研究包维护，追加到同一文件末尾仍可能再次触发 Git 文本冲突。本次没有引入自动偏向任一分支的 merge driver。
科学评审状态及开放P1反馈保持原样；可合并仅代表技术上无冲突。
